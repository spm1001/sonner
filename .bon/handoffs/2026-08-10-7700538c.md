## For Claudes to come

**A guarantee that removes a failure mode usually removes its signal too — and the signal was doing work.** Three instances landed in one session, and the shape is identical each time. Clipping an HTML sheet with `overflow: hidden` guarantees it cannot spill onto a second page; what it actually does is convert "you can see the overflow on page two" into "the content is cut off mid-sentence and the page count still reads 1". Passing a stale `session:@window` target to tmux used to be impossible because session names were stable; now that they are not, tmux resolves it to nothing and *exits 0*, so a caller checking the return code sees success. And a probe written as `tmux display -t X -p 'resolved'` prints "resolved" for any input at all, because the format string is a literal — the check cannot fail, so it has never been tested.

The trap is that each of these feels like an improvement while you are building it. You add the clip *because* the overflow was a problem; you get a mechanism that is correct by construction and a failure mode that is now invisible. So the rule that falls out is: **when you make something impossible, ask what used to tell you it had happened, and replace that.** For the printed sheet, the replacement is rendering the PDF to an image and looking at it every single time — a page count is not a check. For the tmux coordinate, it is asserting on the resolved session name rather than on the exit code. For the probe, it is putting a real field in the format string so that a bad target produces visibly empty output.

This is the same family as `verification.md`'s "a check that has never failed has never been tested", pointed at a different moment: not the check you inherited, but the check you have just made unnecessary. Newly-added safety is exactly when nobody thinks to re-derive what the old noise was for.
